# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Opis projektu

Strona internetowa dla firmy BlockchainWares - software development company z Dąbrowy Górniczej, specjalizującej się w blockchain, EDA, engineering i bazach danych.

## Komendy

```bash
npm run dev                        # Dev server na localhost:4321
npm run build                      # Build produkcyjny do .vercel/output/ (adapter @astrojs/vercel)
npm run preview                    # Podgląd builda
npm test                           # Playwright E2E, 154 testy (chromium 149 + chromium-no-js 5)
node scripts/hash_password.mjs     # Generuje ADMIN_PASSWORD_HASH z hasła podanego interaktywnie
npx tsc --noEmit                   # Type check
```

## Tech Stack

- **Astro 5** w trybie **SSR** (`output: "server"`, `@astrojs/vercel@9` adapter) + **React 19** (client:load dla interaktywnych sekcji)
- **Tailwind CSS 4** z **DaisyUI 5** (custom theme "blockchainwares")
- **Framer Motion 12** (animacje sekcji)
- **TypeScript** (strict mode via astro/tsconfigs/strict)

## Deploy

Vercel, autodeploy z gita. Build wychodzi do `.vercel/output/` (adapter `@astrojs/vercel`), nie `dist/server/entry.mjs`.

`Dockerfile` i `compose.yml` zostają w repo jako alternatywa dla VPS, ale są NIESPÓJNE z obecnym adapterem — `CMD`/`HEALTHCHECK` wskazują na `dist/server/entry.mjs`, który przy `@astrojs/vercel` w ogóle nie powstaje (Dockerfile ma na to komentarz ostrzegawczy). Powrót na VPS wymaga najpierw cofnięcia adaptera na `@astrojs/node`.

## Architektura

Full-stack SSR (Astro + React Islands). **Żadna strona marketingowa nie jest prerenderowana** — jedyny prerender w repo jest na `/404`. Wydarzenia migrowały z lokalnej stałej na moduł w `elysia-backend` (patrz niżej), a status `ongoing/upcoming/past` musi liczyć się na żywo na każdej z nich (banerze, liście, detalu), więc `index.astro` i `markets.astro` straciły `prerender = true`, które miały wcześniej — inaczej lista wydarzeń zamroziłaby się na dniu builda. Middleware **wykonuje się teraz dla wszystkich trzech** (`/`, `/markets`, `/markets/<id>`) i ustawia im nagłówki bezpieczeństwa; `vercel.json` (reguła 1, negative lookahead na `/api` i `/admin`) ustawia te same wartości **równolegle**, nie zamiennie — zostaje świadomie, bo to jedyne źródło, które dosięga prerenderowanego `/404`, plików statycznych i dokłada HSTS (middleware nie chodzi po żadnym z nich). Oba źródła muszą zgadzać się co do wartości: `tests/security_headers.spec.ts` porównuje `src/lib/net/security_headers.ts` z `vercel.json` i wywala się na rozjeździe.

Endpointy `/api/admin/logs`, `/api/admin/stats` i hook `use_admin_logs` zostały usunięte. CRUD wydarzeń (`/admin/events/*`) trzyma się tej samej zasady: same natywne `<form method="post">`, żadnego `fetch` po stronie panelu mimo tego, że dane teraz żyją w zewnętrznym API — `tests/admin_events.spec.ts` ma wariant bez JS dokładnie z tego powodu. Panel działa przy wyłączonym JavaScripcie — nie dodawać `fetch`/`XHR` przy kolejnych zmianach.

**Jedyny wyjątek: podgląd wydarzenia na `/admin/events/new` i `/admin/events/<id>/edit` — świadoma decyzja właściciela, nie przeoczenie.** Formularz ma od razu pokazywać, jak wpis wygląda w banerze, na karcie i na własnej stronie, a to da się policzyć tylko w przeglądarce, więc `src/components/admin/EventPreview.tsx` jest wyspą React `client:load`. Wyjątek jest wąski i taki ma zostać:

- podgląd czyta **wyłącznie** DOM formularza i **nie wysyła żadnego żądania** — zakaz `fetch`/`XHR` z panelu obowiązuje dalej, pilnują go `tests/admin_events.spec.ts` i `tests/admin_event_preview.spec.ts`;
- zapis pozostaje natywnym `<form method="post">` na tę samą stronę. Bez JavaScriptu formularz zapisuje się tak samo — traci się sam podgląd. Żadne pole ani przycisk zapisu nie może zależeć od skryptu;
- `<noscript>` w `AdminLayout.astro` chowa `[data-event-preview]`, żeby bez JS nie zostawał martwy przełącznik wariantów. Sam atrybut niesie stan hydracji (`static` przed nią, `live` po), bo przed hydracją przyciski są w DOM, ale jeszcze nie działają;
- `PreviewFont.astro` doklada do `<head>` font landingu (Quicksand) przez slot `head` — panel chodzi na foncie systemowym i bez tego podgląd pokazywałby właściwy układ w niewłaściwym kroju.

## Zmienne środowiskowe

Wymagane w runtime (nie na etapie builda) — bez nich `get_auth_config()`/`get_log_source_url()`/`get_events_api_url()`/`get_events_api_key()` rzuca i aplikacja nie startuje:

- `ADMIN_PASSWORD_HASH` - hash hasła admina, generowany przez `node scripts/hash_password.mjs`
- `AUTH_SECRET` - sekret do podpisu ciasteczka sesji, min. 32 znaki
- `LOG_SOURCE_URL` - URL zdalnego logu nginx. Ścieżka zawiera token — to sekret, nigdy w kodzie/repo
- `EVENTS_API_URL` - bazowy adres modułu wydarzeń w `elysia-backend` (bez końcowego ukośnika — patrz `src/lib/env.ts`). Wskazuje na host **omijający Cloudflare** (`api-direct.bard-dev.com`, DNS only), nie na `api.bard-dev.com` — Cloudflare blokuje (403) server-side fetch z Vercela do tego drugiego po bot score/ASN. Nie "poprawiać" z powrotem na `api.bard-dev.com`, patrz pułapka w `src/lib/events/` wyżej i pattern KB `cloudflare-blocks-vercel-ssr-fetch-to-own-api`
- `EVENTS_API_KEY` - klucz serwisowy do zapisu wydarzeń (`X-API-Key`). Odczyt listy jest publiczny i klucza nie używa; mutacje bez niego kończą się `misconfigured`, nie próbą zapisu

Opcjonalne:

- `LOG_SOURCE_TTL_SECONDS` - jak długo pobrany log żyje w cache procesu, w sekundach (domyślnie 300)
- `EVENTS_API_TTL_SECONDS` - jak długo odpowiedź modułu wydarzeń żyje w cache procesu, w sekundach (domyślnie 300)
- `SESSION_NOT_BEFORE` - kill-switch unieważniający wszystkie sesje bez rotacji `AUTH_SECRET`
- `SITE_ORIGIN` - kanoniczny origin dla guardu CSRF; brak = `site` z `astro.config.mjs`

Nigdy nie wpisywać realnych wartości tych zmiennych do repo/dokumentacji.

## Testy

`npm test` (Playwright, 220 testów: chromium 215 + chromium-no-js 5, w 18 plikach speców) korzysta z lokalnych fixture'ów — logu (`tests/fixtures/`, nie uderza w prawdziwy `LOG_SOURCE_URL`) i modułu wydarzeń (`tests/fixtures/serve_events.mjs`, serwer HTTP ze stanem w pamięci procesu, adres wstrzyknięty jako `EVENTS_API_URL` w `playwright.config.ts` — nie uderza w prawdziwy `elysia-backend`). Projekt `chromium-no-js` weryfikuje, że panel admina (w tym CRUD wydarzeń) **zapisuje** bez JavaScriptu — nie że widać w nim podgląd; wariant bez JS sprawdza wprost, że panel podglądu jest wtedy schowany. Osobny test pilnuje, że z panelu nie wychodzi żaden request XHR/fetch. Specy panelu: `tests/admin.spec.ts` (ogólny przepływ), `tests/admin_traffic.spec.ts` (7 flag filtrów ruchu), `tests/admin_countries.spec.ts` (karta krajów + `showCountryIps`), `tests/admin_events.spec.ts` (pełna ścieżka dodanie/edycja/usunięcie przez listę z potwierdzeniem, odrzucony zapis wraca z wpisanymi wartościami, brak sesji przekierowuje z każdej z 4 tras, zero XHR/fetch z frontu, wariant bez JS), `tests/admin_event_preview.spec.ts` (podgląd nadąża za nazwą i datą, wszystkie trzy warianty, wpis bez daty tłumaczy brak wariantu w banerze, prefill edycji trafia do podglądu, zero XHR/fetch — **żaden test w tym pliku nie zapisuje**, bo stan fixture'a należy do `admin_events.spec.ts`, a pliki chodzą równolegle na jednym serwerze i `reset_events()` stąd zabrałby tamtemu rekord), `tests/nginx_parser.spec.ts` (budżet rekordów — degradacja na wstrzykniętej małej wartości, bez przeglądarki).
